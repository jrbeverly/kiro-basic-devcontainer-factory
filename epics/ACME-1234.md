# mTLS-only static site on CloudFront

## Goal

Serve a static site from S3 through CloudFront that refuses any client which does
not present a certificate issued by a certificate authority we control. The whole
arrangement is defined in Terraform in this repository.

## Context

- Every consumer is a script or a service. There are no browsers, no sign-in, no
  human-facing error pages, and no requirement for a friendly failure mode.
- Client identity is established at the CloudFront edge with viewer mTLS, so the
  origin performs no authentication of its own.
- CloudFront validates client certificates against a trust store, which is an
  account-level CloudFront resource loaded once from a PEM CA bundle in S3. The
  trust store does not stay in sync with the bundle after it is created.

## Constraints

- No AWS Private CA. The CA is generated in Terraform with the `tls` provider,
  and its certificate is the entire contents of the trust store bundle.
- Keep the component count as low as CloudFront allows: an S3 bucket for site
  content, the CA bundle object, a CloudFront trust store, and one distribution.
  Anything beyond that has to be forced by CloudFront, not chosen.
- Terraform is the only provisioning mechanism. No console steps, no scripts that
  create infrastructure.
- Do not run `terraform apply`, and do not run any command that calls AWS. Work
  stops at `terraform fmt`, `terraform init -backend=false`, and
  `terraform validate`.
- The end-to-end check is written and reviewed but never executed here.

## Open questions

- Viewer mTLS may require the distribution to serve an alias with an ACM
  certificate rather than the default `*.cloudfront.net` domain. If it does, the
  component budget grows by a certificate and its DNS validation. Record the
  finding before adding either.
- A distribution using viewer mTLS needs an HTTPS-only viewer protocol policy and
  HTTP/3 disabled. Confirm both against the provider schema rather than assuming
  the defaults are already correct.

## Stories

### 1. Certificate authority

Generate a self-signed CA and one client certificate signed by it. Expose the
client key pair so the end-to-end check can use it.

### 2. Content origin

An S3 bucket holding a single object, reachable only by CloudFront.

### 3. Trust store

Publish the CA certificate as a PEM bundle in S3 and create the CloudFront trust
store from it.

### 4. Distribution

One distribution in front of the bucket, with viewer mTLS in required mode bound
to the trust store. Expose its domain name.

### 5. End-to-end check

`examples/default` deploys the arrangement and re-exports what the check needs. A
script beside it requests the object with the client certificate and again without
it, expecting a success and a TLS failure respectively, reading every value it
uses from `terraform output`.
